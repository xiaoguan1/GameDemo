实现跨节点通信功能细节
	消息种类：异步（无需等待接收方的响应）、同步（需要等待接收方的响应）
	消息数据中必须附带 主动发送方 的节点信息(即"ip:port") 以及 服务地址(string or number)。
	消息类型整合：rpc协议类型占用1个字节、服务的协议类型占用3个字节

	异步消息：无需附带session，但还是带上节点信息和服务地址，虽然不带上感觉也行，但为了完整性或者方便后续追查但是带上吧，并且也就固定几个字节不存在浪费。

	同步消息：必须附带session，因为需要对方的响应数据。

	超时限制：3秒

	心跳机制：
		间隔5秒进行一次发送。若在5秒内有消息发送出去，则该5秒内不需要发送心跳了。

		按节点类型来区分谁向谁发送心跳消息。目前是游戏服(即main_node结点) 向 其他节点发送心跳消息。而跨服节点向中心服节点发送心跳消息。被发送方 判断保活机制是 9*5 秒没有任何消息来则直接关闭socket。
		注释：因为socket的keepalive过于慢，不做保活机制有可能会形成死链而造成资源来不及释放的情况。故必须做保活机制。此外，如果有了保活机制关闭keepalive可以吗？看着是可以的，但还是维持skynet引擎的默认开启keepalive机制~~~


	打包处理流程：a服务需要跨节点通信，则a服务需要先进行消息打包，并发送到dpcluster服务，dpcluster服务再将节点信息进行二次打包，最终发送到对应节点。

	注释：review一下cluster.lua代码，参考一下云风的代码

	目标：使用单个socket 或者 两个socket（发 和 收各一个）必须支持配置且不支持热更

	玩法跨服a->玩家服b->目标玩法跨服c->回到玩家服b->回到玩法跨服a
	玩法跨服a->中心服->玩法跨服b->中心服->玩法跨服a


	集群：
		仲裁网关节点：作用是判断玩家要登陆那个玩家服节点。判断玩家是否需要创角
		玩家服节点（n个）：承载玩家，和玩家个人的玩法逻辑等等

		问题1：玩家的在线唯一性
			登录的时候，必须先跑到仲裁服，让其分配连接那个玩家服节点。（顶号，则还要通知其下线处理）
			玩家下线处理，则需要通知仲裁服设置好相关标记



	节点类型：user玩家服节点、cross一般跨服节点、adhoc临时节点（热门的玩法、仲裁网关节点）
		user节点：在线玩家、和玩家自己有关的内容（会有1到n个，共享一个user数据库）
			玩家会固定去某一个user节点，并且user节点也会起邮件服（拉数据的时候需要根据集群编号和区服id 作为复合主键）
		合服操作、合集群操作

		cross节点：不高频一些服务，帮派等等
		adhoc节点：比较吃处理器资源的热门玩法（当然简化版本是把game节点的内容 合并到 cross节点中。）


	新增概念：
		1.机器节点 和 lua服务节点。机器节点通过数据库的server_config配置获取、lua服务节点根据namedsvr获取
		2.机器节点 和 lua服务节点 有可能一样也有可能不一样。不一样则代表 lua服务节点 “寄生” 在机器节点中，一样则是“本地lua服务”

		3.目前仅有user、cross、adhoc节点。在我看来 中心服节点仅仅只是由几个特定作用的服务组成。若在cross节点代为启动，则cross节点也具有中心服的作用，即充当了中心服的角色。
			但目前不打算把所有节点压缩为一个节点（即一个skynet进程）。最少是user节点和cross节点（即两个skynet进程），感觉从理论上出发是完全可以实现的，但是逻辑上会相对繁琐一些，不想给自己太多心智负担。。。。。。。。
	
	跨节点通信格式期望：
		rpc.mod_call.服务名称[网络地址].模块名称.函数名称(参数1, 参数2, ...)
			网络地址：目前来讲只能通过中心数据的server_config这张表来获取了，但中间的介质、流程暂时没想好~~~~~
			服务名称、模块名称、函数名称：手动填写即可，但传入gcluster服务之前必须在本地服务做好检查校验（一般来讲，正常的检查校验几乎无任何性能损失，即使有也是很微小。除非代码的实现有很大的问题,做了某些频繁的多余操作）

		rpc.lua模块 每个服务都需要加载，并且提前设置好。若需要热更机制则只需在__update__回调进行重新的设置即可，注意不要有阻塞操作！！！否则会引起多协程带来的运行错误！！！

命名规则：
	全局方法命名规则：大驼峰（例如 PascalCase），只能使用字母和数字
	局部方法命名规则：小驼峰（例如 camelCase），只能使用字母和数字
	
	全局变量：全小写并使用 下划线_ 进行拼接（例如：aa_bb_cc）
	常量、宏、枚举值：全大写并使用 下划线_ 进行拼接（例如：AA_BB_CC）

	局部变量：小驼峰（例如 camelCase）



	任何方法内都不能创建全局变量，仅能在代码前面事先声明
